# 0003. 弹窗实例把手只往下传 id

日期: 2026-08-20
状态: 已接受

## 背景

底座原先通过 context 往弹窗组件里注入一个实例把手对象, 上面挂着 `resolve` / `cancel` /
`requestClose` / `setBusy` / `registerGuard` / `notifyClosed` 六个方法, 以及 `visible` / `busy`
两个状态字段.

这个对象在挂载点里按 `[id, visible, busy]` 记忆化, 也就是说: 弹窗每进一次提交态、每开始一次退场,
它都是一个新对象. 而外壳层要用它, 于是 `useModalShell` 里的 `submit` / `close` 都把它当依赖,
再往上 `modalProps` 又把这两个回调当依赖 —— 一个 `useMemo` 攒出四项依赖
(`[close, confirmLoading, instance, submit]`), `useCloseGuard` 也得把 `instance?.id` 与
`instance?.registerGuard` 拆出来单独当依赖, 才躲得开对象身份的变化.

## 判据

**那六个方法本来就是稳定的.** 它们全是 `modalStore.xxx(id, ...)` 的转发, 而 `modalStore` 是模块级
单例, 函数身份永不改变. 把稳定的东西裹进一个随状态重建的对象再发下去, 下游就得为这个壳付依赖比较的钱.

所以 context 只传 `id` 这一个原始值, 命令直接调 `modalStore` 上的模块级函数, 反应式状态
(`visible`)按字段订阅、交出布尔原始值. 依赖项从对象降为原始值之后, 上面那条链整段消失.

这与 zustand 文档里「把 action 定义在 store 外的模块顶层」是同一个形状 —— 命令不需要 hook 才能调.

对外交出的回调(`submit` / `close` / `handleFinish`)用包内的 `useEvent` 锁住身份, 契约因此可以
升级为「原语身份稳定, 调用方可以放进自己的依赖数组」, 这是原先给不出的保证.

## 被否决的方案

**只把那个 `useMemo` 删掉.** 它确实该删(载体不是 memo 组件, 省不下任何渲染), 但删完依赖链还在,
换个地方还会长出来. 这是症状不是病因.

**用 React 19.2 的官方 `useEffectEvent` 锁身份.** 本仓 `react-hooks` 规则直接报错:
它的产出「不许赋给变量, 也不许作为 props 下传」(实测), 而我们的 `submit` / `close` 正是要交给
antd Modal 的 `onOk` / `onCancel`.

**照社区常见写法在渲染期写 ref.** antd 的地基 `@rc-component/util` 就是这么做的, 但
`react-hooks/refs` 会拦下来, 而那条规则是对的 —— 渲染应无副作用. 改用 `useInsertionEffect`,
它是提交阶段最早跑的一个, 窗口小到只剩「同一次提交的渲染与插入副作用之间」, 而本包交出去的回调
全部由用户交互触发, 都在提交之后.

**把 `useEvent` 的约束写成 `(...args: any[]) => any`.** 看着比 `Function` 贴切, 但它带调用签名,
会给内联箭头的参数列表定下上下文类型, 参数类型于是静默失效 —— `useEvent((x = 1) => x + 1)` 里的
`x` 成了 `any`, 之后传字符串也不报, 而 tsc 全绿. 改成 `A extends unknown[]` 同样是上下文类型,
只是把静默换成刺耳(报 x is of type unknown). 取 `Function`(React 官方给 `useEffectEvent` 的形状)
才让参数从注解与默认值自己推. 用例钉在 `packages/components/src/modal/types.typetest.tsx`,
约束改回去那几条 `@ts-expect-error` 会哑掉, tsc 以 TS2578 失败.

**用函数重载去掉实现里最后一次类型转换.** tsc 干净且零转换, 但基础 eslint 的 `no-redeclare`
不认 TS 重载会报警告; 为一个函数把全局规则换成 TS 版不值, 所以留着那次向外的转换.

**接入 React Compiler 让手写记忆化整体退场.** 收益更彻底, 但要改构建链并要求全量代码守
Rules of React, 是独立一件事. 本次不做, 入口记在
`.design/plans/2026-08-20-依赖数组的开源设计综述与选型.md`.

## 代价

**`useModalInstance` 从公开导出里消失**, 换成 `useModalId`. 这是破坏性变更; 当时三处调用点全在包内、
应用层零使用, 所以选在此刻改.

**`visible` 的订阅从一处变成两处**: 挂载点订阅实例列表, 外壳再自己订阅一次显示态. 两者读同一个 store,
不会打架, 代价是多一次订阅.

**「不做 memo」这条判据依赖于载体不是 memo 组件.** 哪天 `BaseModal` 真的包上 `memo`, 这条要重新算.

**`useEvent` 的闭包有一个提交期内的滞后窗口.** 见上. 若日后有非交互触发的回调要用它, 先重新审视这条.

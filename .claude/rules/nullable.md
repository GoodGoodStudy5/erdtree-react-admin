# 字段的可空性

- 字段一律写 `?: T`, 不写 `| null`. 后端给 null 还是压根不给这个字段, 界面上是同一件事.
- 例外只有一种: null 自身承载业务语义 —— 「不适用」「尚未建立」这类, 与「上游没给值」不是一回事.
  这时写 `?: T | null`, 并在 TSDoc 里说清这个 null 读作什么, 如「现阶段恒空: 应付组还没开始建」.
  说不出读作什么就不是例外.
- 响应拦截器**不做** null → undefined 的转换. 代价认下: 类型写的是 undefined, 运行时收到的是 null.
- 因此判空一律走 `??` / `?.` / `eR`, 它们对 null 与 undefined 一视同仁.
  **禁止 `=== undefined`** —— 它在运行时漏掉 null, 而类型不会报错.
- 前端自造的类型 (页面内部的状态、表单值) 不在此列, 那些值不经过 JSON.
